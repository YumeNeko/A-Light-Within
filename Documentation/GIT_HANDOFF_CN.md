# Git / GitHub 后续交接

当前目录已经是独立工程，但**未创建远程仓库、未登录 GitHub、未推送或公开任何文件**。`Library`、`QA` 和本机构建输出由忽略规则排除，不应提交。

## 推荐公开内容

- 项目 README、设计说明、操作指南、真实测试记录和资源来源说明。
- 你有权公开的项目代码、新玩法配置、场景以及所需 .meta。
- 可再分发的资源，连同完整来源和许可证。
- 后续录制的真实演示素材；不要把尚未测试的内容描述为已完成。

## 不公开内容

- Unity Library、Temp、Logs、UserSettings、编译产物、下载源压缩包和大体积 Windows 构建目录。
- Unity 许可证、账号数据、机器标识、带个人路径/账号信息的原始日志。
- 旧课程提交包、个人学号文档，以及无权公开再分发的第三方素材。

项目级 `.gitignore` 默认排除 Starter Assets 等需单独核对授权的第三方目录。因此**它不是已经验收的一键克隆即运行仓库**。公开前可选择只展示自有核心代码与设计资料，或整理依赖获取步骤并保留可公开的修改补丁。不能因为素材免费就自动认为可以把源资源放进公开仓库。

## 后续操作顺序

1. 先通过新版实际试玩验收。
2. 选定公开代码范围，确认所有资源、字体和依赖的许可。
3. 只在当前独立工程根目录初始化仓库，不要把上一级其他 Unity 项目整体上传。
4. 加入 README、版本说明、真实截图和下载入口；试玩包独立发布，仓库中不堆叠二进制包体。
5. 在一个干净目录验证依赖获取与打开流程，再由你确认仓库名称、可见性和发布内容后推送。

无需现在购买 GitHub 服务或下载额外插件。当前没有对公开链接、仓库可访问性或下载可运行性作验证。
