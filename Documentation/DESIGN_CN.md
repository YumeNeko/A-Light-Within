# 《心灯》玩法与系统设计 v0.1

## 1. 设计目标与边界

将原课程作业的探索、解谜和危险段落整理成可完整体验的单人原型，用于展示需求拆解、配置维护、可玩性迭代和 AI 协作能力。美术目标是比例正常的贴图角色、清晰路径和统一色调，不追求商业大作资源量。

设计假设：玩家通过「观察线索 → 选择能力 → 操作机关 → 看见环境变化 → 抵达新区域」的循环，能够理解三种能力并在终局组合运用。此假设尚需真实玩家测试，不作为已经验证的结论。

叙事调整：删除小女孩同伴，不再转移能力给另一个人。三个品格都是主角自己的成长。安全通行机关源自课程对障碍交互及绕行的要求，求职版保留为低压力体验路径；树根桥没有旁侧传送，必须先完成桥梁机关。

范围不包含：多人联机、复杂战斗、装备与抽卡、开放世界、跨会话存档、移动端适配。

## 2. 三种能力

| 能力 | 教学与作用 | 关键反馈 | 终局验证 |
| --- | --- | --- | --- |
| 洞察（1） | 揭示完整眼纹；选择真门；唤醒回声路径 | 线索由隐藏变可见，假门反馈错误，真门打开 | 在眼纹台揭示梦魇真身 |
| 共鸣（2） | 回应动物石碑；旋转引流方向；升起实体桥梁 | 动物移动、引流连线、桥面升起、出口打开 | 旋转引流盘，连接核心 |
| 勇气之光（3） | 暂时驱散追逐区域的暗幕并减缓梦魇 | 玩家光环、持续时间条、追逐速度变化 | 在北侧灯座使用勇气完成终局 |

早期机关明确提示能力，承担教学；终局通过独立机关、能力切换、方向选择与前置条件验证掌握程度。所有机关统一为单击 E，避免长按占用注意力。

## 3. 完整流程

| 区域 | 玩家任务 | 可观察的状态变化 | 完成后 |
| --- | --- | --- | --- |
| 回声庭院 | 洞察真实之眼、选择完整门印、唤醒回声碑并沿脚印穿过门洞 | 门纹显现、真门转开、脚印出现 | 在第一盏心灯领悟共鸣 |
| 共鸣林地 | 按顺序回应两座石碑、旋转引流盘并激活树根桥 | 两只动物走向桥前、连线出现、桥面从谷底升起 | 出口心灯授予勇气并开门 |
| 长夜回廊 | 躲避落石、点亮灯塔、通过移动浮台或安全点到达远岸、穿越追逐 | 落石预警、光环、远岸收集确认、梦魇追逐和击退 | 通向终局并设检查点 |
| 心灯圣所 | 洞察台揭真身 → 共鸣台转向并连接 → 勇气台解核心 | 假象消失、核心连线亮起、护盾解除、终章光效 | 结局与重新开始/退出菜单 |

虚空段落没有整层兜底地板。收集判定在远岸，不绑定站上浮台；正常跳跃和安全通行均应取得相同旅程进度。危险死亡返回最近检查点，已解开的机关保留。

## 4. 机关数据

`PuzzleDefinition` 是 Unity ScriptableObject，生成后每个机关一份配置资源。

| 字段 | 含义 | 调整风险 |
| --- | --- | --- |
| id | 唯一标识，逻辑与前置条件引用 | 不随意改名；目前环境动作仍由 id 分派 |
| title / clue / hint | 名称、一层线索、直接提示 | 可安全修改，但要匹配实际场景 |
| ability / kind | 所需能力、交互类型 | 影响能力校验及操作方式 |
| prerequisites | 完成前必须取得的标识 | 错误引用或循环会造成卡关 |
| radius | 交互距离 | 默认 2.1 米；假门 1.5 米；仍要求无遮挡视线 |
| initialRotation / targetRotation | 四个方向中的初始值和目标值 | 0=北，1=东，2=南，3=西；需要与场景标记一致 |
| milestone | 旅程计数编号 | 0 不直接增加旅程进度；不能重复冒充不同目标 |

节点依赖摘要：

`truth → door → memory → memory_arrival → insight_growth → fox → deer → bridge_align → bridge → forest_growth → light → crossing → pursuit → boss_reveal → boss_link → boss_core`

`memory_arrival / crossing / pursuit` 是区域到达状态，不是可按 E 的机关。假门不会完成。三个安全节点重复使用，不增加机关完成状态；目的地到达判定负责推进对应旅程。

## 5. 状态与失败处理

- 未满足前置：机关暗色，拒绝交互，提示先完成当前目标。
- 可以操作：显示能力色，靠近且没有墙体遮挡才显示操作面板。
- 交互：进入范围且视线无遮挡时显示提示，单击 E 立即校验能力、方向和前置条件。
- 错误能力：红色闪烁、失败声音和线索；不会解锁后续。
- 方向错误：要求旋转，不允许靠长按绕过方向判断。
- 完成：机关变色、成功声、玩家脉冲和对应环境变化。
- 死亡/手动返回：保留已完成状态，回到安全落点。

关键参数集中：移动 3.3 m/s、疾跑 5.5 m/s、跳高 1.15 m、光芒 10 秒、移动浮台周期 5.5 秒、落石预警 0.85 秒。数值是初始设计值，不是已通过用户实验得出的最优值。

## 6. 可测量的迭代

本机会话记录事件：能力切换、错误选择、方向旋转、提示使用、完成机关、安全点、死亡和结局。默认只保存在内存，不联网、不收集身份数据。显式测试模式可以输出本机测试文件。

建议招募 3–5 位未玩过项目的人，记录：首次找到机关时间、错选能力次数、桥梁是否被理解为通路、浮台跌落次数、是否需要口头提示以及通关时长。不要将开发者熟悉路线的通关表现当作新手表现。

优先处理：阻断流程的问题 → 控制和镜头 → 路线/线索理解 → 反馈区分 → 装饰细节。求职展示需至少保留一条真实的「反馈—修改—复测」链路。

## 7. 架构取舍

当前为轻量原型：机关文案、时长、前置条件已数据化，但地图坐标、部分环境对象名称与完成后的动作仍集中在 Director/Builder 中，不是通用商业化关卡编辑器。下一步可将环境动作拆成独立事件组件，降低硬编码和场景命名耦合；不应在面试中声称这一点已完成。
