# 项目讲解与面试准备

这份资料是理解和练习提纲，不是虚构经历的简历文案。仅讲述你实际确认、能够演示并解释的内容。当前版本已完成 Unity 构建和自动回归，真实键鼠完整通关与陌生玩家测试仍待作者执行，不能将自动验证说成已通过全部发布验收。执行记录见 QA_STATUS.md。

## 1. 建议的项目定位

《心灯》是从课程项目迭代而来的单人第三人称解谜原型，探索玩家如何学习并组合运用洞察、共鸣、勇气三种能力。你提出主题和需求，使用 Codex 辅助实现，再根据试玩反馈调整。角色、植物、动物等使用有来源记录的免费资源。

不要称它为商业级完整游戏，也不要以“全栈独立手写”“原创建模”描述并非你完成的工作。AI 辅助是方法，需求判断、解释能力、验证质量才是展示重点。

## 2. 三分钟展示顺序

1. 约 30 秒：项目背景、求职方向、原课程项目的主要问题和本轮取舍。
2. 约 45 秒：展示一道教学机关，解释为什么提示、能力选择和失败反馈必须一致。
3. 约 45 秒：展示树根桥。指出动画必须同时改变可通行状态，玩家实际从桥上通过，而不是看一段旁侧动画。
4. 约 30 秒：展示终局三步机关，说明前置条件、错误能力和方向校验。
5. 约 30 秒：展示一份配置和一条真实测试记录，解释改动前后、AI 做了什么、你验证了什么。

这里的时间是讲解分配建议，不是游戏通关时长实测。没有完成验收前，不录制或描述为最终发布版本。

## 3. 面向两个主要岗位

### 玩法策划

重点讲：核心循环、教学到终局的递进、为什么采用解谜解开 Boss 而不是加战斗、危险与安全路径如何服务目标用户。

需要能够回答：“如果玩家不看说明，你如何知道他理解了共鸣？”可用真实测试观察支撑，例如是否主动看动物移动、是否识别桥前方向标记、是否明白桥升起后可以走。未开展测试前只能说这是待验证的问题。

### 系统策划

重点讲：机关配置、依赖关系、状态切换、失败处理和异常情况。可以打开同一份配置说明哪些字段可安全调整，哪些字段改变后必须修改视觉标记或脚本。

不要将目前的轻量数据化称为完整系统平台。部分行为仍依赖对象名称和 id 分支，可以主动说明它适合当前原型规模，以及未来如何拆分为环境动作组件。

### 测试岗位补充

展示边界思维即可：错误能力是否通过、暂停是否还能交互、传送后是否漏记进度、重新触发落石能否死亡、只有桥模型没有碰撞是否会掉落。不要为了展示测试经历而捏造覆盖率或 Bug 数量。

## 4. 你应该能解释的 C# 逻辑

| 位置 | 应能说明的问题 |

| PuzzleDefinition | 为什么数据放到独立资源，配置和行为各负责什么 |
| PuzzleNode | 锁定、就绪、完成之间怎样切换；错误时如何显示反馈 |

| HeartlightDirector.UpdateProgress | 为什么远岸到达判定同时支持跳跃和安全通行 |
| HeartlightDirector.Respawn | 死亡重置哪些状态，哪些机关进度应保留 |

| DreamRockfall / HeartlightHazard | 预警、重力、实际碰撞、冷却与重置如何配合 |
| HeartlightVerification | 自动测试覆盖什么，为什么仍需要真实键鼠测试 |

## 5. 诚实说明 AI 协作

可按以下结构自己组织语言：

- 你负责：主题、优先级、需求确认、实际试玩、提出问题、确认取舍。只保留你实际做过的事项。
- AI 辅助：实现 C#、批量场景处理、草拟文档和测试工具。
- 第三方资源：Kenney 模型与贴图、Noto 字体、原项目所用 Unity 组件。
- 你的验证：列出你实际读懂的脚本、亲手调整的参数与重复测试的步骤。
- 局限：不是多人/战斗项目，尚未积累正式用户研究或商业上线数据。

若被问“没有 AI 能做什么”，不需要夸大。可以现场解释一个方法，手动修改一份配置并观察结果，说明哪些 Unity 操作仍在学习。

## 6. 可作为真实迭代案例的历史问题

以下是用户曾反馈的问题，不等于求职版已经全部验收通过：角色过大、女孩出生点错误、视线遮挡、桥梁动画与碰撞通行不一致、引导穿墙、浮台收集只认可站台、不合理地板兜底、菜单鼠标失效。

选择你最熟悉的一例，用四句讲清：发现什么 → 为什么影响体验 → 怎么修改 → 用什么复现步骤确认没有回归。不要只展示修复后的截图而无法说明问题。

## 7. 投递前个人检查

- 能独立打开正确的 Unity 场景并完成一次试玩。
- 能说明至少一份配置及其依赖关系。
- 能解释至少两个核心 C# 方法，不需要背整份文件。
- 至少亲手做一次小修改，保留真实前后对照。
- 能明确说出 AI 和第三方资源的边界。
- 新试玩版已经通过完整流程、真实输入与打包目录检查。
- 简历中的“已完成”“已验证”与 QA 状态一致，没有伪造通关率、帧率或用户反馈。
